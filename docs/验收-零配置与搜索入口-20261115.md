# 验收：零配置安装 ＋ 会话搜索入口位置（2026-11-15）

> 对象：`dsh-session-query-cjk` v0.3.0 ／ 运行环境：DeepSeek Harness `@deepseek-ai/dsh-desktop-runtime 0.2.2-rc.3`（Electron 44.7.0，内置 Node 24.21.0 / SQLite 3.53.4）
> 结论一句话：**11-15 收工报告里"零配置只做了一半"这一项已经不是"没验证"，而是"当时根本跑不起来"——schema 把 `path` 声明成必填，构造前的校验就抛错。本轮已修，并用可复现的探针拿到通过证据。**

---

## 一、上一版报告的判断错在哪（三处，均已回源码核对）

| # | 上一版说法 | 源码事实 | 判定 |
|---|---|---|---|
| 1 | 「`openAt` 默认值 `startup` → `first-search`，已定」 | `lib/index.js` 静态 Config 里写的是 `.default("startup")`（改前的 L629），只有 `resolveConfig()` 里才有 `config.openAt ?? "first-search"` 的回退。而 cordis **先按 schema 校验并填默认值，再构造实例**，所以回退永远走不到：**生效值一直是 `startup`** | **错**（改的是死代码） |
| 2 | 「`path` 未配置时回落 `~/.dsh/cache/session-query-cjk.db`，已定」 | 同上：`resolveConfig()` 里的回落逻辑存在，但 schema 是 `path: z.string().required()`，校验阶段就抛 `ValidationError: invalid config: $.path missing required value` | **错**（回落逻辑跑不到） |
| 3 | 「更新后的界面取消了会话搜索入口，这是零配置验证受阻的直接原因」 | 0.2.2-rc.3 的 `dsh-client-ui-workspace` 仍在渲染搜索入口：`WorkspaceBrowser.tsx` L1226–1282 的放大镜按钮＋输入框，快捷键 `session.search`（`shortcuts.ts` L83，`KeyK`＋`primary`） | **错**（入口没被删，是折叠成了图标） |

第 1、2 条是同一个病根：**默认值写在了两个地方，schema 那份才是生效的**。

## 二、本轮改动（`lib/index.js`，三处）

```diff
-		path: z.string().required(),
+		path: z.string().default(""),
 		openAt: z.union([
 			"startup",
 			"first-search",
 			"never"
-		]).default("startup"),
+		]).default("first-search"),
```

```diff
-		aliasFile: typeof config.aliasFile === "string" ? config.aliasFile : "",
+		aliasFile: typeof config.aliasFile === "string" && config.aliasFile.trim().length > 0
+			? config.aliasFile
+			: resolve(homedir(), ".dsh", "cache", "session-query-aliases.json"),
```

- `path` 改成默认为空串 → 校验通过 → `resolveConfig()` 的回落逻辑真正执行 → 落在 `~/.dsh/cache/session-query-cjk.db`。
- `openAt` schema 默认与 `resolveConfig()` 对齐成 `first-search`（避开启动期 sessions 服务未就绪、建出空库的时序问题）。
- `aliasFile` 不写时落到约定路径 `~/.dsh/cache/session-query-aliases.json`（文件不存在＝不扩展，`refreshAliases()` 的 `statSync` 会静默返回）——让"零配置"也能吃到别名与拼音，不必改 `cordis.patch.yml`。
- `node --check` 退出码 0。

## 四、验证二：默认路径 ＋ 真实索引库 → 字级搜索真的通

做法：把本机现役索引库（88 会话／19,035 文档／92,250,112 B）复制进假 HOME 的默认路径，**仍然不写任何 config**，跑 7 个查询（limit=5）：

| 查询 | 命中会话数 | 说明 |
|---|---|---|
| 林家 | 5（页内上限） | 双字命中 |
| 林 | 5（页内上限） | **单字命中**——字级索引的直接证据 |
| 林晚秋 | 5（页内上限） | 三字命中 |
| 册子 | 5（页内上限） | 口语词原样命中 |
| 香包 | 0 | 别名表未配置 → 不扩展（设计如此） |
| 林晚丘 | 0 | 拼音层只覆盖别名表内的词 → 不配置别名表就不生效（设计如此） |
| abcdef999 | 0 | 不存在字符串 |

每条命中的 `bestMatch.sessionId === header.id`、`surface` 全为 `current`——满足 `dsh-api-session-controller` `list.ts` L269–281 的准入条件（每个会话只留最强命中，且要求是当前视角的 user/assistant 消息）。

> 「香包／林晚丘 为 0」不是回归：拼音层的 `PY_INDEX` 只由别名表构建（`buildPyIndex()` 遍历 `ALIAS_MAP`），别名表为空则拼音层无事可做。上一版报告里「香包 2,494 篇」「林晚丘＝林晚秋」是**配了 `aliasFile`** 时的数据。零配置下要别名/拼音，看下一节。

## 五、验证三：零配置 ＋ 别名表放约定路径 → 别名与拼音一起活

做法：假 HOME 里放 `<fakehome>/.dsh/cache/session-query-aliases.json`（内容只有 `{"香包":["香囊"],"林晚秋":["林晚秋"]}`），**仍然不写任何 config**，同一个现役索引库：

| 查询 | 命中 | 说明 |
|---|---|---|
| 香包 | **5**（改前 0） | 约定路径的别名表被自动加载，`香包→香囊` 生效 |
| 林晚丘 | **5**（改前 0） | 拼音层把 `林晚丘` 归一到 `lin|wan|qiu` → 命中「林晚秋」，结果与直接搜「林晚秋」一致 |

即：**用户装完包，只需把一份 `session-query-aliases.json` 丢进 `~/.dsh/cache/`，三层能力全开，不必改动 `cordis.patch.yml`。** 数字摘要见 [`../dev/evidence/README.md`](../dev/evidence/README.md)。

## 六、会话搜索入口在哪（把「丢失的入口」找回来）

DeepSeek Harness 0.2.2-rc.3 **没有删掉搜索**，它被收进了一个图标：

| 入口 | 位置 | 出处 |
|---|---|---|
| 鼠标 | 左侧栏「会话／工作区」分组标题行右端的**放大镜按钮**，点一下展开输入框（仅侧边栏展开时渲染） | `dsh-client-ui-workspace/src/client/rows/WorkspaceBrowser.tsx` L1208–1282 |
| 键盘 | **Ctrl+K**（网页版 Ctrl+Alt+K） | 同上 `shortcuts.ts` L83：`register('session.search', …, 'KeyK', ['primary'], …)` |

链路：输入 → `searchSessions()`（`index.ts` L171）→ Host RPC `session.search`（`dsh-api-session-controller`）→ `listState.search()` → **本插件 `searchSessions`**。

**界面只列几条**的机制（这是上一版报告里"只出 1 条"的正解方向）：客户端 `deriveSearchResults()`（`tree.ts` L534–591）先做本地标题/工作区/会话号匹配，再并入 Host 内容命中；**只有 `list.byId` 里存在、且通过 `sessionVisible()`（当前会话／归档过滤）的会话才会成行**，合并结果上限 20（`SESSION_SEARCH_RESULT_LIMIT`）。所以「库内命中 80 个会话、界面只列 N 条」是客户端可见性过滤＋上限，不是索引丢数据。具体某次只出现 1 条，需要给出当时的查询词和是否开了"显示归档"才能定位——本轮不复现。

## 七、一个坑（会误导后来者，务必记住）

**在本工作区目录里用 node 跑 SQLite 落盘，写入会被静默丢弃**：`CREATE TABLE` 不报错、`INSERT` 报 `no such table`、文件停在 0 字节；换到平台临时目录（`%TEMP%`）就正常。所以探针脚本的 HOME／索引库必须放在 `%TEMP%` 下，不要放在 `<工作区>\_tmp`。这与插件本身无关，是沙箱落盘限制。
